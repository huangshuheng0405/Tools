# Grill Me 笔记

> 来源：mattpocock/skills（https://github.com/mattpocock/skills）
> 更新时间：2026-09-29（基于仓库 main 分支最新状态整理）

## 一句话定位

**grill-me** = 对你（用户）的计划/设计进行"毫不留情"的连环追问，直到把方案里每一个隐藏假设、每一个未决的分支都问清楚，达成"共享理解"。

它本质是一个**对齐工具**：软件失败最常见的根因是"你以为对方懂，其实没懂"。grill-me 用追问把这条沟通鸿沟填平。

## 核心机制：设计树（design tree）

把整个方案当作一棵**决策树**来走：

- 每个决策会分叉出"挂在它下面"的子决策
- 按**轮次（rounds）**推进，而不是一问一答
- **前沿（frontier）** = 所有"前置条件已确定、现在就能问"的问题集合
  - 也就是：不用靠猜还没有答案的问题，此刻就能问的那些

## 一轮问询的格式

每一轮把整个前沿一次性抛出，每个问题编号 + 给出你的推荐答案，然后停下来等用户回答：

```
❓ Q1 - <问题标题>: <问题正文，可以多段，含多个选项>

➡️ <你的推荐答案>

---

❓ Q2 - <问题标题>: <问题正文>

➡️ <你的推荐答案>
```

要点：

- 每个问题**先给推荐答案，再提问**
- 一轮里问题之间用 `---` 分隔
- **问完一轮就停，等用户回答后再进入下一轮**（不要一口气问完所有轮）

## 推进规则

1. 每轮用户的回答会**重塑这棵树**：已定的决策把前沿往外推，解锁依赖它的新问题
2. 重新计算前沿 → 问下一轮
3. **依赖同轮里尚未回答的问题的，属于"下一轮"，不属于本轮**

## 事实归我，决策归你

- **查事实是 agent 的活，不是用户的活。** 前沿问题如果需要环境里的事实（文件系统、工具等），派子 agent 去查，不要问用户任何你能自己查到的东西
- **不要阻塞等待**：正在跑的子 agent 查询只是一个"未定的前置条件"，只有它下游的问题才需要等；其余前沿现在就问
- **决策才是用户的事**：把每个决策摆给用户，然后等

## 何时结束

**前沿为空**时结束——即设计树的每个分支都走过了，没有任何东西是"默默假设"的。

结束前，在用户确认你们已达成共享理解之前，**不要动手执行**。

## grill-me vs grill-with-docs vs grilling

最新版仓库里，"grill" 相关技能拆成了三层：

| 技能 | 类型 | 定位 |
|------|------|------|
| **grilling** | model-invoked（可复用原语） | 底层追问原语，`grill-me` / `grill-with-docs` / `triage` / `wayfinder` 等背后的通用机制 |
| **grill-me** | user-invoked | 纯对话式追问，**不读不写文档**，方案还在概念阶段时用 |
| **grill-with-docs** | user-invoked | 追问锚定到项目已有的领域模型（CONTEXT.md、ADR），术语对照术语表校验，定下来的决策实时写回文档 |

选择标准：

- 项目**还没有**领域模型 / CONTEXT.md → 用 **grill-me**
- 项目**已有**领域模型，新方案需要与之对齐 → 用 **grill-with-docs**

## 安装指令

来自上游 README（30 秒安装），两条路线二选一：

### 方式一：Claude Code 插件（订阅式，自动更新）

```bash
claude plugins install mattpocock-skills
```

或直接在会话内：

```
/plugin install mattpocock-skills
```

> 已上架 Claude Code 官方市场，无需额外配置，随上游更新自动同步。整套作为只读 bundle 安装。

### 方式二：skills.sh（可编辑，按需挑技能）

适用于 Codex 及其他 agent：

```bash
npx skills@latest add mattpocock/skills
```

安装器会列出技能清单让你勾选——**记得把 `grill-me` 选上**。它会以普通文件形式写入你的项目，归你所有、可自由改，不会后台自动更新。

需要拉上游最新改动时：

```bash
npx skills update
```

> 两条路线别同时装，否则每个技能都会重复一份。

### 装完后跑一次 setup

在每个仓库里跑一次（首次使用前）：

```
/setup-matt-pocock-skills
```

它会问你：用什么 issue tracker（GitHub / Linear / 本地文件）、triage 时用哪些标签、文档存哪里。

## 触发时机

- 用户想对计划/设计做压力测试（stress-test）
- 用户说 "grill me" / "challenge my thinking"
- 动手实现前，想暴露隐藏假设或未解决的权衡
